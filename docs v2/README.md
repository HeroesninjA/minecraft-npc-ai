## Purpose

- migrate documentation here gradually without disrupting the existing `docs/` flow;
- keep only final, verified, useful content;
- avoid stale ideas, contradictions, abandoned docs, and unverified text.

## Proposed structure

- `canonical/` - reference docs and current project state;
- `architecture/` - maps, relations, contracts, and technical design;
- `guides/` - tutorials and step-by-step instructions;
- `operations/` - runbooks, deploy, debug, backup, and maintenance;
- `planning/` - roadmap, phases, backlog, and priorities;
- `reference/` - checklists, schemas, and catalogs;
- `archive/` - historical docs kept for context only.

## Migration rules

- add a document here only when it has a clear purpose and status;
- if a document is outdated, move it to `archive/` or rewrite it;
- if documents contradict each other, keep one canonical source;
- do not copy speculative ideas without a label or justification.

## Work order

1. Identify the document.
2. Assign the category.
3. Rewrite it cleanly if needed.
4. Move it into the new structure.
5. Mark old documents as archived or replaced.
