# Taskuri de lucru concrete

Acesta este backlog-ul de implementare curat, nu un ghid de design.

## Principiu

- fiecare task trebuie sa produca schimbare concreta in cod sau verificare automata;
- taskurile deja implementate raman marcate ca istoric;
- documentul este util pentru prioritizare si executie, nu pentru arhitectura de fond.

## Zone acoperite

- AI orchestration;
- quest si progres;
- GUI pe roluri;
- world, NPC si spawn;
- debug, testare si release;
- modularizare, Kotlin si addonuri.

## Folosire

- trateaza acest backlog ca lista de lucru curenta;
- muta taskurile finalizate in arhiva istorica sau in documentele canonic-corecte;
- actualizeaza starea taskurilor cand se schimba implementarea.
